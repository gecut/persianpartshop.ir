# گزارش بازگشت UI و اصلاح محدود تأمین

تاریخ: ۲۰۲۶-۱۱-۰۹
مرجع تحلیل و برنامه: [supply-request-ui-restoration-plan.md](supply-request-ui-restoration-plan.md)
وضعیت: اصلاح محلی UI و آزمون‌ها انجام شد؛ انتشار انجام نشده است.

## نتیجه

- فایل کارت محصول از `HEAD=11693c0` بازیابی و فقط برای نشانه/اقدام استعلام در کاتالوگ مشترک سازگار شد. انتخاب و لغو انتخاب مستقیم، انتخاب چندمحصولی و ورود به صفحهٔ قبلی تعیین مقدار برگشتند.
- `product-quantity-modal.tsx` حذف شد؛ محاسبه و تصمیم‌گیری تکراری آن روی موجودی تجمیعی کلاینت نیز حذف شد.
- صفحهٔ تعیین مقدار، اسلایدر، NumberField، برآورد و تأیید سفارش قبلی حفظ شدند. اقدام ghost کوچک «درخواست تأمین» برای کالای دارای امکان تأمین اضافه شد؛ مقدار اولیه فقط به پیش‌نویس تازه منتقل می‌شود. پیش‌نویس موجود همان محصول بازنویسی نمی‌شود.
- فرم تأمین قبلی بدون انتخاب انبار استفاده می‌شود. ثبت جدید به preview معتبر سرور وابسته است؛ بازیابی pending مستقل باقی مانده و در صفحهٔ تعیین مقدار نیز نمایش داده می‌شود. برگشت به خرید در صورت تغییر مقدار سبد تأیید صریح می‌گیرد.
- جزئیات محصول نیز برای کالای استعلامی اقدام تأمین دارد؛ لینک مستقیم محصول با آزمون مرورگر بررسی شد.
- کارت سفارش در فید مشترک به سطح بدون حاشیه، تصویر ۱۳، نوار خلاصهٔ تیره، شعاع ۲xl و اقدام‌های ارتفاع ۱۰ برگشت. کارت تأمین از همان نقش‌های بصری استفاده می‌کند. فیلترها هندسه و رنگ‌های قبلی دکمه‌های آیکون‌دار را دارند.
- عبارت‌های داخلی منبع/انبار از فرم و تاریخچهٔ مشتری حذف شدند؛ داده‌های legacy دست‌کاری نشدند.
- API، قرارداد، CMS و migration در این نوبت تغییر نکردند. تغییرات قبلی این بخش‌ها در workspace حفظ شدند.

این بازگشتِ ظاهر و تعامل با حفظ قابلیت‌هاست؛ تمام فایل‌های وب به نسخهٔ قدیمی جایگزین نشده‌اند، زیرا مصرف قرارداد جدید و فید مشترک باید باقی بماند. جزئیات تصمیم دربارهٔ دو فرم مقدار موجود در پلن ثبت شده است.

## شواهد راستی‌آزمایی

| بررسی | نتیجهٔ مشاهده‌شده |
|---|---|
| `pnpm --filter @persianpart/web exec tsc --noEmit` | موفق |
| `pnpm --filter @persianpart/web build` پس از آخرین تغییر کد | موفق؛ ۱۱۲۴۶ ماژول؛ هشدار اندازهٔ chunk بالاتر از ۵۰۰ کیلوبایت |
| `pnpm --filter @persianpart/web exec playwright test` | ۱۹ passed، یک skipped، ۳۴٫۸ ثانیه |
| `git diff --check -- apps/web .agents/brain/supply-request-ui-restoration-plan.md` | بدون خطا |

آزمون supply با fixture شبکه، انتخاب مستقیم بدون دیالوگ، نگهداری کالای قبلی سبد، انتقال مقدار ۸۰ به خرید و فرم تأمین، قطع ارتباط، retry با همان کلید، storage failure، preview failure، فید مشترک و عدم نمایش انتخاب انبار را پوشش می‌دهد. آزمون warehouse موجود نیز انتخاب انبار، migration پیش‌نویس، جداسازی حساب/تب و مسابقهٔ ثبت را پاس کرد.

تصاویر واقعی مرورگر با دادهٔ fixture در عرض‌های ۳۶۰ و ۱۲۸۰ بررسی شدند؛ بررسی DOM در هر دو عرض، نبود overflow افقی را تأیید کرد:

- `/tmp/persianpart-history-restored-1280.png`

مقایسه با کد baseline انجام شده است؛ screenshot diff پیکسلی با نسخهٔ قبل اجرا نشده و برابری پیکسلی ادعا نمی‌شود. ظاهر در موبایل و دسکتاپ همچنان در قاب SPA فعلی قرار دارد. CSS یا token سراسری، فونت و کتابخانهٔ تازه‌ای اضافه نشده است.

## حدود اعتبار

تست زندهٔ Web→API→CMS به‌علت فعال نبودن `SUPPLY_BROWSER_LIVE` و نیاز به محیط disposable اجرا نشد. نتیجهٔ ۱۹ تست به‌معنی تأیید یکپارچگی زنده یا دادهٔ پروداکشن نیست. هیچ عملیات دیتابیس، push یا deploy انجام نشد.
